# ISO-Tool language parity and synchronization

ISO-Tool uses one behavioral contract across its language front ends. Python is the reference orchestration layer; native C++ and .NET provide Windows desktop integration and expose the same toolchain/artifact concepts.

## Shared stages

1. Toolchain detection
2. Dependency resolution
3. Recursive repository/source analysis
4. Build and link planning
5. Parallel compile/assemble/link
6. Artifact collection
7. Spit Fire BIOS/UEFI boot artifact handling
8. ISO/IMG staging and mastering
9. Verification and provenance reporting

## Shared repositories

- ChimeraIIOS
- BizX
- BizXtreme

## Artifact contract

`src/<repo>` preserves source provenance; `bin` contains executables; `lib` contains libraries; `boot-images` contains boot artifacts; `metadata`/`manifests` contain machine-readable reports.

The detector is intentionally side-effect free unless environment persistence is explicitly requested. Native front ends may consume the JSON report generated by the Python engine or run their native detector for UI presentation.

The two repositories containing ISO-Tool (`amerhwitat/nlp` and `amerhwitat/ChimeraIIOS`) are kept structurally aligned for the shared engine contract. Changes should be mirrored rather than allowing divergent behavior.
